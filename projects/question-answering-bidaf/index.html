Reproducing a landmark question-answering model from the paper

A from-scratch implementation of BiDAF [arXiv:1611.01603], a pre-transformer machine-comprehension network, that reached 83.5 exact match on SQuAD v1.1, within about a point of BERT’s reference result.

Context
Independent paper reproduction, started as an undergraduate, years before LLMs
My role
Implementation, training the model from scratch, tuning, and mentoring the team
Benchmark
SQuAD v1.1, dev set
Code
github.com/parikhKadam/bidaf-keras

The problem

To answer a question from a passage, a model has to read the passage with the question in mind. The dominant approach at the time squeezed the passage into one fixed-size vector early, before attention was applied, which throws away the fine detail needed to pinpoint an exact answer. BiDAF’s idea is to let attention flow between passage and question at every step and pass it forward, rather than collapsing it.

The task: given a Wikipedia passage and a question, return the answer as a contiguous, verbatim span of the passage. Nothing is generated. In SQuAD v1.1 every question is answerable.

Result

83.5 EMMy implementation, SQuAD v1.1 dev set (exact match)
84.2 EMBERT’s contemporary reference result (91.1 F1)

Exact match requires the normalized prediction to equal a reference answer exactly, so it is the stricter of the two standard metrics. I did not record F1 for this run, so I only state the exact-match figure.

What I did

  • Translated the paper into a from-scratch TensorFlow and Keras implementation of its five layers and trained the model from scratch, end to end, for answer-span prediction on SQuAD v1.1.
  • Diagnosed and resolved convergence and accuracy bottlenecks through iterative experimentation and hyperparameter tuning.
  • Built the data preprocessing pipeline so training and evaluation saw consistent inputs.
  • Mentored teammates on attention mechanisms and machine-comprehension design, and ran knowledge-sharing sessions on deep learning and question answering.

The five layers

  1. 1 · Word embedding

    Pretrained GloVe and fastText vectors, concatenated, for every passage and question token.

  2. 2 · Contextual encoding

    A shared bidirectional LSTM turns each sequence into context-aware representations, passage and question separately.

  3. 3 · Attention flow

    The core contribution. A passage-question similarity matrix gives attention in both directions: which question words matter for each passage word, and which passage words matter most given the question. These flow forward at every position instead of being pooled into one vector.

  4. 4 · Modeling

    A second bidirectional LSTM over the attention output, so it models interactions that attention has already shaped rather than raw embeddings.

  5. 5 · Output

    Two heads give a probability for every passage position being the start of the answer and for being the end. Inference picks the start and end pair with the highest combined probability and returns the text between them.

Beyond the paper: no input length cap

The original BiDAF caps the number of input words, so longer passages are cut off. Mine has no fixed cap: memory is the only limit, and I have run it on one full article as the passage.

Limits

  • The paper embeds characters with a CNN to handle rare words. My implementation uses concatenated GloVe and fastText word vectors instead, so it is not an exact replica.
  • It also trains on SQuAD v2.0, which adds unanswerable questions. A marker token is prepended to the passage, and an unanswerable question is trained to select that token as its answer. The 83.5 EM above is the v1.1 result.
  • Recurrent encoders read sequentially, so they train more slowly than the fully parallel transformer encoders that followed.
